# Окончательный план разработки веб-сервиса для сборки SVG-иллюстраций

Общий индекс с зависимостями, оценками и порядком выполнения: [`tasks/README.md`](tasks/README.md).

## 1. Зафиксированный объём

### Реализуемые сценарии

1. **Метафора или заголовок**
   - Пользователь вводит текст.
   - LLM через OpenAI-compatible API выбирает объекты и их роли.
   - При недоступности API используется локальный подбор по тегам и синонимам.
   - Детерминированный layout engine размещает объекты.
   - Пользователь может отредактировать результат и экспортировать SVG.

2. **Явный список компонентов**
   - Пользователь вводит названия объектов.
   - Сервис сопоставляет их с библиотекой, проверяет совместимость и автоматически создаёт композицию.

### Библиотека

- 10 типов объектов.
- 2 состояния каждого объекта: главное и фоновое — всего **20 логических иллюстраций**.
- 2 варианта детализации каждого объекта: L и S.
- Полный набор — **40 SVG-вариантов**.
- Исходные файлы находятся в:

```text
misc/figma-task/library/Библиотека компонентов
```

- Используется только встроенная библиотека; импорт пользовательских SVG не реализуется.
- Довыгрузка ассетов и доступ к Figma для реализации не требуются.

### Композиции

- Форматы:
  - `1000×1000`;
  - `1200×630`;
  - `800×1200`.
- В одной автоматической композиции:
  - 1–3 главных объекта;
  - дополнительные фоновые объекты и декор.
- Главные объекты:
  - полностью находятся внутри холста;
  - не перекрывают друг друга существенно.
- Фоновые объекты и декор могут перекрываться и частично обрезаться.
- Если набор не помещается в выбранный формат, применяется **единый коэффициент масштабирования композиции**: относительные размеры объектов сохраняются.
- Пользователь может выбрать S вручную, если composition-level масштаб его не устраивает.

### Трансформации

Разрешены только:

- перемещение;
- поворот;
- дублирование;
- удаление;
- изменение порядка слоёв.

**Масштабирование отдельных объектов запрещено.** Размер объекта определяется только исходным вариантом L/S.

Допускается **масштабирование композиции целиком** — один общий коэффициент, применяемый ко всем объектам сцены. Он вычисляется автоматически, чтобы композиция поместилась в выбранный формат. Относительные размеры объектов при этом сохраняются, и пропорции между объектами не меняются.

### Цвет

- Встроенные схемы Purple, Warm и Aqua.
- Автоматическая перекраска всей сцены по цветовым ролям.
- Загрузка пользовательской палитры из JSON:
  - название;
  - 4 цвета фона;
  - 4 цвета объектов.
- Цвета фонов могут использоваться в объектах.
- Цвета объектов не могут использоваться в фонах.
- Главные объекты остаются цветными, фоновые — монохромными.

### Хранение

- Одна текущая сцена хранится локально в **IndexedDB**.
- После перезагрузки страницы сцена восстанавливается.
- Сохраняются также пользовательские палитры.
- Серверное хранение, аккаунты, несколько проектов и история версий отсутствуют.

### Технологии

- **Frontend:** Vue 3 + Quasar UMD, SVG DOM.
- **Backend:** Django, endpoint для LLM proxy.
- **LLM:** сменный OpenAI-compatible API через `base URL`, модель и API-ключ.
- **Контейнеризация:** Docker + Docker Compose.
- Django отдаёт frontend и API по одному origin.
- Отдельный контейнер базы данных не требуется: композиции и палитры хранятся в IndexedDB браузера.
- Основной способ запуска:

```bash
docker compose up --build
```

- После запуска сервис доступен по адресу:

```text
http://localhost:8000
```

### Проверка и сдача

- Актуальные desktop Chrome и Firefox.
- Мобильные Chrome и Firefox.
- Responsive UI и сенсорное управление редактором.
- Локально запускаемый проект, репозиторий, README и демонстрация.
- Эталонные примеры: «Обучение», «Финансы», «Технологии».
- Команда: один разработчик.

**Оценка:** **15–20 человеко-дней**, включая мобильную адаптацию, Docker Compose, тестирование и резерв.  
**Календарный ориентир:** **3–4 недели**.

## 2. Архитектурный контур

```text
Vue 3 + Quasar UMD
   ├── Библиотека и параметры сцены
   ├── SVG-редактор
   ├── Импорт палитр
   └── Экспорт
          │
          ▼
   Scene Store / JSON-модель
          │
          ├── SVG Renderer
          ├── Layout Engine
          ├── IndexedDB
          └── SVG Serializer

Метафора → Django LLM Proxy → OpenAI-compatible API
                        └────→ Локальный fallback
```

### Контейнерный запуск

```text
Docker Compose
   └── web
       ├── Django API
       ├── Django LLM Proxy
       ├── Static frontend
       └── Healthcheck
```

Модель экземпляра объекта содержит только:

- `instanceId`;
- `assetId`;
- `role`;
- `x`, `y`;
- `rotation`;
- `zIndex`.

Свойства `scale` в модели нет. В SVG допускаются только трансформации `translate` и `rotate`.

**Задачи**

- Проверить целостность локального набора из 40 SVG-вариантов.

  `SVG → Vue/SVG DOM → поворот → перекраска → экспорт`.
- Проверить выбранный OpenAI-compatible API и structured JSON response.
- Проверить SVG-экспорт в Chrome и Firefox.
- Создать структуру репозитория и конфигурацию окружения.

**Зависимости:** локальная библиотека SVG и параметры LLM API.

**Оценка:** **0,5 ч-д**.

**Критерии приёмки**

- Все 40 SVG-файлов доступны и читаются.
- Сложный объект проходит цикл без растеризации и потери структуры.
- LLM возвращает машинно проверяемый JSON.
- Секреты вынесены в `.env`, репозиторий содержит только `.env.example`.

## 5. Общие критерии приёмки

1. Оба сценария создают композицию только из встроенной библиотеки.
2. Поддерживаются 10 типов, два состояния и L/S.
3. Все 40 исходных SVG-вариантов доступны и проходят валидацию.
4. Работают три формата и ограничение 1–3 главных объекта.
5. Доступны только перемещение, поворот, дублирование, удаление и управление слоями.
6. Отдельные объекты не масштабируются: в модели объекта нет свойства `scale`. Масштаб композиции — один общий коэффициент на всю сцену, сохраняющий относительные размеры объектов.
7. Относительные размеры и геометрия объектов не изменяются.
8. Непомещающиеся комбинации отклоняются с понятным сообщением.
9. Встроенные и загруженные JSON-палитры автоматически перекрашивают сцену без нарушения цветовых ролей.
10. Текущая сцена и пользовательские палитры восстанавливаются из IndexedDB.
11. Экспортированный SVG самостоятелен, векторен и редактируем на уровне групп и внутренних элементов.
12. AI выбирает только объекты и роли; неизвестные ID отклоняются.
13. При недоступном AI работает локальный fallback.
14. Основной сценарий работает в desktop и мобильных Chrome и Firefox.
15. На мобильных устройствах доступны все операции редактирования без hover и клавиатуры.
16. Проект запускается на чистом окружении командой `docker compose up --build` без установки зависимостей на хост.
17. Репозиторий содержит три примера, демонстрацию и документацию.

## 6. Основные риски

| Риск | Митигация |
|---|---|
| Повреждённые или некорректно размеченные SVG | Автоматическая валидация всех 40 файлов, визуальная проверка и контроль неизменности геометрии |
| Набор не помещается в формат | Применяется общий коэффициент масштабирования композиции с сохранением относительных размеров; пользователь может переключить L/S вручную |
| Ошибки координат и bounding boxes при повороте | Единый координатный слой и отдельные unit-тесты геометрии |
| Сенсорные жесты конфликтуют с прокруткой страницы | Pointer Events, `touch-action`, pointer capture и проверка на мобильных устройствах |
| Панели редактора перегружают мобильный экран | Компактные вкладки и выдвижные панели с приоритетом холста |
| Различия SVG и скачивания файлов между Chrome и Firefox | Ранняя проверка экспорта в обоих браузерах, стандартный `Blob` и download-ссылка |
| Неверная разметка цветовых ролей | Ручная проверка manifest и тесты перекраски каждого ассета |
| Некорректные пользовательские палитры | JSON Schema, HEX-валидация и конкретные ошибки без изменения текущей сцены |
| AI возвращает неизвестные ID или нестабильный JSON | Structured output, whitelist, валидация, mock-тесты и локальный fallback |
| Потеря редактируемости при экспорте | Ранний технический spike и проверка standalone SVG во внешних редакторах |
| Повреждение данных IndexedDB | Версия схемы, валидация при восстановлении и безопасный сброс |
| Утечка LLM API-ключа | Только Django backend, `.env`, `.dockerignore`, проверка frontend, образа и репозитория |
| Невоспроизводимый Docker-запуск | Фиксация зависимостей, чистая сборка, healthcheck и проверка запуска по README |
| Увеличение сроков из-за четырёх тестовых окружений | Автоматизировать общие проверки и зарезервировать время на ручное мобильное тестирование |
| Расширение объёма дополнительными функциями | Не добавлять индивидуальное масштабирование объектов, импорт SVG, аккаунты, несколько проектов, undo/redo и серверное хранение без отдельной оценки |
