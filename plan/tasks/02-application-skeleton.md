# Задача 02. Каркас приложения, backend, модель сцены и Docker Compose

## Цель

Создать запускаемый каркас Django + Vue 3 + Quasar UMD с адаптивным UI, моделью сцены и воспроизводимым Docker-запуском.

## Задачи

- Создать Django-проект и frontend-страницу на Vue 3 + Quasar UMD.
- Настроить Django для отдачи frontend и API по одному origin.
- Реализовать адаптивную компоновку:
  - панель сценариев;
  - параметры;
  - SVG-холст;
  - панель объектов и слоёв;
  - экспорт.
- На мобильных экранах использовать компактные вкладки или выдвижные блоки.
- Определить структуры `Scene`, `ObjectInstance`, `Asset`, `Palette`.
- Реализовать единый store и отделить состояние сцены от состояния редактора.
- Добавить endpoints `/api/interpret-metaphor` и `/api/health/`.
- Добавить `Dockerfile` и `compose.yaml` с сервисом `web`.
- Настроить установку зависимостей, запуск Django, порт `8000`, переменные окружения и healthcheck.
- Добавить `.dockerignore`, исключающий `.env`, `.git`, кэши, виртуальное окружение и временные файлы.

## Зависимости

- Задача 00.
- Для окончательной интеграции библиотеки — задача 01.

## Оценка

**1–1,5 человеко-дня.**

## Критерии приёмки

- Проект запускается командой `docker compose up --build` без локальной установки Python и зависимостей.
- Frontend, backend и healthcheck доступны после запуска контейнера.
- Сервис доступен на `http://localhost:8000`.
- Интерфейс пригоден для desktop и mobile.
- Сцена сериализуется в JSON без SVG DOM.
- Модель экземпляра содержит только `instanceId`, `assetId`, `role`, `x`, `y`, `rotation`, `zIndex`; свойства `scale` нет.
- Django не передаёт API-ключ во frontend и не встраивает его в Docker-образ.
- `docker compose down` корректно останавливает сервис.
