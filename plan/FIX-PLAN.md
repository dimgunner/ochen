## P0 — блокеры релиза

### P0-1. Восстановление формата холста из IndexedDB

**Где:** `static/app.js:33-52` (`mounted`), `static/scene-store.js`.

**Проблема:** после `SceneStore.restore()` подставляется `scene` с сохранённым
`format`, но `canvasFormat`, `canvasWidth`, `canvasHeight` остаются дефолтными
`1000x1000`. Сохранённая композиция 1200x630 открывается в формате 1000x1000
и обрезается.

**Что сделать:**

- валидировать `restored.scene.format`;
- сопоставить `{w, h}` с ключом `Layout.FORMATS`;
- выставить `canvasFormat`, `canvasWidth`, `canvasHeight`;
- не запускать watcher формата и повторную раскладку при восстановлении:
  использовать флаг `restoring` или выставлять значения до присвоения `scene`;
- при неизвестном формате откатываться к `1000x1000` с предупреждением.

**Готово, когда:** сохранение в 1200x630 -> перезагрузка -> селектор и холст
1200x630, координаты объектов не изменились, авто-раскладка не сработала.

**Оценка:** 0,25 ч-д.

### P0-2. «Масштаб 100%» не должен ломать композицию

**Где:** `static/app.js:368-375` (`resetScale`).

**Проблема:** `checkFit().ok` может быть `true` при `scale < 1`, после чего
безусловно применяется `applyPlacement(1)`. Объекты выходят за холст без
сообщения об ошибке.

**Что сделать:**

- использовать возвращённый `fit.scale`;
- применять `1` только если `fit.scale >= 1 - epsilon`;
- иначе сохранять текущий масштаб и показывать сообщение о том, что композиция
  не помещается в 100%;
- скрывать или дизейблить кнопку, когда 100% невозможны.

**Готово, когда:** 3 L-объекта при авто-масштабе 29% -> нажатие «100%» не двигает
объекты и даёт понятное сообщение.

**Оценка:** 0,1 ч-д.

### P0-3. Drag при CSS-уменьшении холста

**Где:** `static/app.js:323-339` (`startDrag` / `onDrag`), `app.js:271-284` (`svgPoint`).

**Проблема:** экранные пиксели прибавляются напрямую к SVG-координатам. При
отображении холста шириной 754 px вместо 1000 объект отстаёт от курсора примерно
на 25%.

**Что сделать:**

- переводить указатель в координаты SVG через `svg.getScreenCTM().inverse()`
  вместо ручного пересчёта через `getBoundingClientRect()`;
- использовать ту же функцию в `startRotate` / `onRotate`;
- хранить стартовую точку drag в SVG-координатах.

**Готово, когда:** при любом CSS-масштабе объект следует за курсором 1:1 на
desktop и mobile.

**Оценка:** 0,25 ч-д.

### P0-4. Ручные правки не сбрасываются при добавлении объекта

**Где:** `static/app.js:229-243` (`addObject`), `app.js:376-385`
(`applyPlacement`), `static/layout-engine.js:229-249` (`place` сбрасывает
`rotation = 0`).

**Проблема:** любое добавление или авто-действие заново раскладывает все объекты
и обнуляет повороты. Пользователь не может собрать композицию по частям.

**Что сделать:**

- `addObject` размещает только новый объект, не трогая `x`, `y`, `rotation`
  существующих;
- полный reflow оставить только для явных действий: «Автокомпоновка» и
  подтверждённая смена формата;
- `Layout.place` не должен принудительно обнулять `rotation` при инкрементальном
  размещении;
- для нового объекта искать свободную позицию без существенного перекрытия
  главных объектов.

**Готово, когда:** подвинул/повернул объект -> добавил второй -> первый остался
на месте; «Автокомпоновка» по-прежнему осознанно перекладывает всю сцену.

**Оценка:** 1-1,5 ч-д.

### P0-5. Генерация атомарно заменяет сцену

**Где:** `static/app.js:153-228` (`submitMetaphor`, `submitList`).

**Проблема:** результаты генерации дописываются в текущую сцену. Повторная
генерация накапливает объекты и может дать больше трёх главных объектов.

**Что сделать:**

- собирать новый массив инстансов, не изменяя текущую сцену;
- сначала проверить ответ API, whitelist, лимит главных объектов и
  `Layout.checkFit`;
- только после успешной проверки заменить `scene.instances`;
- при ошибке сети, пустом ответе или непомещающейся композиции оставлять текущую
  сцену без изменений и показывать ошибку;
- после замены сбрасывать `selectedId`, выставлять `scene.scale = fit.scale`,
  сохранять формат и палитру.

**Готово, когда:** генерация «Финансы» после «Обучения» оставляет только
«Финансы»; ошибка API не очищает старую композицию; повторная генерация не
накапливает главные объекты.

**Оценка:** 0,3 ч-д.

### P0-6. Смена формата только с подтверждением

**Где:** `static/app.js:62-78` (watcher `canvasFormat`), шаблон селектора формата.

**Проблема:** смена формата неявно перекладывает всю композицию и сбрасывает
ручные позиции и повороты.

**Что сделать:**

- убрать неявный reflow из `watch: canvasFormat`;
- ввести явный обработчик `requestFormatChange(value)` на `@change` селектора;
- если сцена пустая — менять формат сразу;
- если объекты есть — показывать подтверждение: «Смена формата перераскладывает
  композицию и сбросит ручные позиции и повороты. Продолжить?»;
- при отмене возвращать селектор к прежнему значению и ничего не менять;
- при подтверждении выставлять формат и выполнять reflow; если композиция не
  помещается — откатывать формат и показывать ошибку;
- при восстановлении из IndexedDB выставлять формат через флаг `restoring`, без
  диалога и без reflow.

**Готово, когда:** отмена подтверждения не меняет ни формат, ни координаты;
подтверждение перекладывает сцену; reload не показывает диалог и не делает reflow.

**Оценка:** 0,3 ч-д.

### P0-7. Синонимы в сценарии «Список компонентов»

**Проблема:** поиск идёт только по `name.toLowerCase().includes()` и `assetId`.

**Готово, когда:** `flowers` -> `cveti`, `phone` -> телефонный объект, регистр не
важен; неизвестные перечисляются отдельно.

**Оценка:** 0,25 ч-д.

### P0-8. Лимит 1-3 главных объекта для автоматической генерации

**Где:** `static/app.js` (`commitGenerated`, `submitMetaphor`, `submitList`).

**Проблема:** LLM ограничен тремя объектами, но ручное добавление, дублирование
и повторная генерация позволяли получить 4+ главных объекта. При этом исходная
формулировка плана ограничивает 1-3 объекта именно в автоматической композиции.

**Что сделать:**

- ввести `maxMain = 3` для автоматической генерации;
- `submitMetaphor` и `submitList` обрезают лишние главные объекты и показывают
  неблокирующее предупреждение;
- ручное добавление и дублирование не блокируются;
- при 4+ главных объектах показывать жёлтое предупреждение с рекомендацией 1-3;
- автокомпоновка для 4+ объектов разрешена: она уменьшает сцену и сообщает
  фактический масштаб;
- генерация заменяет сцену (см. P0-5), поэтому не накапливает объекты.

**Готово, когда:** автогенерация оставляет не больше трёх главных объектов,
ручная сборка с 4+ работает без ошибок и сопровождается предупреждением.

**Оценка:** 0,25 ч-д.

### P0-9. Production-обвязка backend и контейнера

**Где:** `backend/api/views.py:62-107`, `backend/core/settings.py`,
`Dockerfile`, `compose.yaml`.

**Проблема:** endpoint без ограничения длины текста и rate-limit; контейнер
запускает `runserver`; `DEBUG` по умолчанию `True`; `ALLOWED_HOSTS` по умолчанию
`*`.

**Что сделать:**

- ограничить длину `text` (400/413) и размер тела запроса;
- добавить rate-limit: nginx или Redis-backed лимитер; `LocMem` подходит только
  для одного процесса;
- `DEBUG=False` по умолчанию в образе; `SECRET_KEY` обязателен;
- `ALLOWED_HOSTS` и `CSRF_TRUSTED_ORIGINS` задавать через env, без `*` в
  production;
- заменить `runserver` на gunicorn/uvicorn; выполнять `collectstatic`;
  отдавать статику через whitenoise или nginx;
- настроить security headers и работу за TLS-прокси
  (`SECURE_PROXY_SSL_HEADER`, HSTS/redirect);
- запускать контейнер не под root; не включать секреты в образ; сохранить
  healthcheck;
- логировать в stdout без ключей и пользовательского текста;
- решить судьбу SQLite: либо volume, либо убрать неиспользуемые
  contrib-приложения и зависимость от БД.

**Готово, когда:** длинный текст не уходит в LLM; частые запросы дают 429;
контейнер запускает production WSGI-сервер; `/api/health/` работает; при
`DEBUG=False` статика отдаётся.

**Оценка:** 0,5-1 ч-д.

## P2 — после релиза или отдельным этапом

### P2-1. Общий планировщик компоновки для любого количества объектов

**Где:** `static/layout-engine.js` (`computeScale`, `checkFit`, `place`).

**Проблема:** все главные объекты всегда ставятся в один горизонтальный ряд;
3 крупных L-объекта дают масштаб 29%, а ручная сборка с 4+ объектами
раскладывается в длинный ряд и сильно уменьшается.

**Решение:** вариант B — общий планировщик для 1, 2, 3, 4, 5+ главных объектов.

- Перебирать количество колонок `c` от `1` до `n`.
- `c = 1` — колонка, `c = n` — ряд, промежуточные значения — сетка.
- Для каждого варианта считать ширину, высоту и требуемый общий масштаб.
- Выбирать вариант с максимальным масштабом.
- Tie-break: широкий формат — больше колонок, портретный — больше строк,
  квадрат — сетка, ближайшая к `sqrt(n)`.
- Центрировать весь блок, каждую строку и объект внутри строки.
- Главные объекты не перекрываются, остаются внутри холста.
- Фоновые объекты по-прежнему ставятся внизу и могут обрезаться.
- Ручное добавление объекта не перекладывает сцену: `placeNew()` сохраняет
  текущую композицию и ищет свободное место.
- Сетка применяется при «Автокомпоновке», смене формата и автогенерации.

**Тесты:**

- 1 объект по центру;
- 2 объекта — ряд или колонка;
- 3 L в 1000x1000 — масштаб заметно больше 29%;
- 3 объекта в 800x1200 — вертикальная раскладка или 2+1;
- 4 объекта — 2x2;
- 5–6 объектов — сетка;
- главные объекты внутри и не перекрываются;
- один общий масштаб;
- ручное добавление не двигает существующие объекты.

Старый тест «10 объектов 2000x2000 не помещаются» пересмотреть: сетка может их
вместить. Заменить на действительно невозможный набор, например 50000x50000.

**Готово, когда:** 3 L в 1000x1000 не требуют масштаба 29%, 4 объекта
раскладываются в 2x2, ручное добавление не перекладывает сцену, существующие
тесты зелёные.

**Оценка:** 2-3 ч-д.
